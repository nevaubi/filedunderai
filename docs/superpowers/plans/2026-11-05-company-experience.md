# Company experience implementation plan

## Ownership

- Root: directory and profile UI, app/router integration, CSS, end-to-end verification, release and evidence summary.
- repo_review: financial date guards, aggregate publication and cache normalization; financial regression tests.
- supabase_security: directory generator/static manifest, professional enrichment backend, authenticated cron and Python tests; read-only security report.
- deployment_review: reusable stock chart, dedicated CSS and tests; final deployment verification when requested.

## Work sequence

1. Finish read-only audit and preserve baseline. Create isolated worktree at `feat/company-experience`.
2. Add failing behavior tests for pending issuer discovery and professional profile source handling; implement separate directory membership without widening screener gates.
3. Build compact directory, company header integration and overview sections. Keep existing research tabs and citations.
4. Implement and integrate the chart using existing price schema and technical engine. Verify sparse/invalid data and cleanup.
5. Implement cached PDL enrichment, issuer matching, safe professional field allowlists, source attribution and quota bounds. Pilot the supplied key without logging it. Publish legitimate source data only.
6. Fix financial consistency and future-date handling with regression coverage. Prepare bounded, reversible legacy repair using existing source proofs and private backups.
7. Run full repository tests and build; independently review each implementation. Inspect desktop/mobile behavior against actual data and a pending issuer.
8. Publish a reviewable branch/PR and preview; verify the exact deployed artifact. Apply only authorized, validated configuration/data repairs. Report delivered behavior, verification and any remaining provider/coverage limits clearly.
